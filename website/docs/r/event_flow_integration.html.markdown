# ilert_event_flow_integration

An event flow integration assigns an inbound integration (e.g. an API or email endpoint) to an existing [event flow][1], so events received through that integration are processed by the flow.

## Example Usage

```hcl
resource "ilert_event_flow" "example" {
  name = "example"

  root_node {
    node_type = "ROOT"
    branches {
      branch_type = "ACCEPTED"
      target {
        name      = "Set variable"
        node_type = "PLAIN"
        metadata {
          var_key   = "context.event.summary"
          var_value = "event from terraform"
        }
      }
    }
  }
}

resource "ilert_event_flow_integration" "example_api" {
  event_flow_id    = ilert_event_flow.example.id
  integration_type = "API"
}
```

## Argument Reference

The following arguments are supported:

- `event_flow_id` - (Required) The ID of the [event flow][1] this integration is assigned to.
- `integration_type` - (Required, ForceNew) The integration type. Same set of values supported by the `integration_type` attribute on `ilert_alert_source` (e.g. `API`, `EMAIL`, `GRAFANA`, `DATADOG`, ...).

## Attributes Reference

- `id` - The ID of the event flow integration.
- `integration_key` - The integration key generated by ilert on create. For `EMAIL`/`EMAIL2` integrations this is exposed as the inbound email address.
- `integration_url` - The fully qualified URL clients should send events to (when applicable for the integration type).

## Import

ilert event flow integrations can be imported using their ID, e.g.

```sh
terraform import ilert_event_flow_integration.example 12345
```

[1]: https://api.ilert.com/api-docs/#tag/event-flows
